# Screen specifications

Canonical route patterns are client routes, not API endpoints. Every screen inherits [interaction](INTERACTION_PATTERNS.md), [tokens](DESIGN_TOKENS.md) and [accessibility](ACCESSIBILITY.md). [Wireframes](WIREFRAMES.md) describe geometry. Entity IDs in routes are stable UUIDs with optional readable key segments; unauthorized routes show a safe unavailable page.

## Approved expansion screens

S01–S18 remain stable. The expanded workspace keeps familiar issues/projects/cycles, uses personal pins and configurable groups, and retains selected rows and origin filters when opening details. Exact colors and geometry must follow the approved compact neutral direction and pass the runtime contrast/accessibility checks; the historical Phase 0 screenshots and teal palette are not a requirement to recreate rejected styling.

Every screen has loading, empty, read-only, denied, narrow/zoomed and error states. Keyboard operations must replace dragging in roadmap, retro grouping, focus ordering and template steps. Destructive or broader-audience operations state exact effects. Demo controls must not survive in a production route as fake persistence or success feedback. S19–S31 are tested through G06–G10 and X01–X66, not just by route existence.

## Cross-screen flows

Golden core flow: S02 create workspace/team → S07 create issue → S06 describe/assign → S03 add project/milestone → S17 plan cycle → S04 filter → S08 rediscover → second account receives S10 update → S18 export. Every step must work without AI, SMTP or GitHub.

Agent flow: S06 Delegate → S12 grant wizard → S14 execution → S16 inspect exact diff/tests → publication → S06 linked PR. A provider completion is only one stage; S16 cannot display verified tests unless the manifest identifies matching head SHA. A failed run can still expose a useful patch with honest failed/incomplete labels.

Context preservation: list/board/search/inbox route carries filter/layout/scroll anchor, and opening issue detail creates a navigable history entry. Screen reader focus follows the opened region; browser Back restores the originating list. API caches are keyed by user/workspace/permission epoch so this context cannot leak across account switches.

## Screen acceptance

Implementation review supplies screenshots at 1440×900 and 768×1024 plus 400% zoom reflow, light/dark, keyboard recording of golden flow, selected error/conflict cases and measured navigation timings. No screenshot of a happy path substitutes for a working permission-denied or offline state. Empty data and 100k issue fixture must share the same components and route model.
