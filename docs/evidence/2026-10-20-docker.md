## Failures, fixes and retrospective

The first actual runtime attempt, [39390350742](https://github.com/MimoAlexer/OpenTrack/actions/runs/39390350742), built both architectures and passed all bootstrap tests, then failed container creation: an unquoted comma split a flow-list `tmpfs` string into a second invalid mount named `mode=1777`. Commit `4fd6130` quotes complete mount strings in local, HTTPS and legacy Compose definitions. Rendering YAML alone had not exposed this Docker daemon failure.

The second run, [39391074727](https://github.com/MimoAlexer/OpenTrack/actions/runs/39391074727), booted both complete stacks but hit an overly strict smoke assertion: the application intentionally serves `/theme.js` outside its hashed `/assets/` bundles. Commit `8a067eb` allows that exact same-origin bootstrap while still requiring bundled JavaScript/CSS and fetching every asset with content-type checks. The subsequent run passed every runtime and HTTPS step on both architectures.

The earlier host-secret route depended on POSIX ownership from the caller's machine. Named volumes and bounded initializer containers move that responsibility into the Linux runtime while keeping privileged credentials out of the serving process. A durable marker and explicit refusal of partial state prevent an apparent convenience repair from disconnecting an existing database from its credentials. Actual startup, persistent state and failure recovery were necessary qualification; a successful image build would have missed both observed problems.

## Remaining boundaries

Actual Windows/macOS Docker Desktop host runs have not been performed. The Linux container images and both native CPU architectures are verified; supported Docker Desktop prerequisites remain explicit. The local Windows development host has no usable Docker engine, so no local container success is claimed.

The HTTPS smoke verifies the production configuration and local-CA transport, not an authenticated HTTPS journey, publicly trusted certificates, external routing or a production security review. Restart/recreation and credential recovery are not a complete database/blob/key backup-and-restore rehearsal. Existing legacy deployments are not silently migrated into the new volume topology. Full populated recovery remains [#46](https://github.com/MimoAlexer/OpenTrack/issues/46), and the application/native-release scope remains in the requirements ledger.
