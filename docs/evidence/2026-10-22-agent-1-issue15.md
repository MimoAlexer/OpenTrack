## Executed behavior

The [PostgreSQL race contract](../../crates/opentrack-app/tests/issue_update_races.rs) gives an owner and a member the same issue ETag. A separately held issue row and observed `pg_blocking_pids` chains establish overlapping writers before release. Both writer orderings pass: exactly one update commits, the other returns the canonical winner as a stale conflict, the version advances once, and only the winner's activity and durable event appear. The losing title, priority or estimate cannot partly apply. Each run uses a fresh migrated schema and restricted runtime credentials in the isolated test database.

The [saved browser workflows](../../web/e2e/issue-conflicts.browser.ts) open two editors against the production frontend and real API/PostgreSQL. Competing saves return exactly one HTTP 200 and one 412. The rejected editor retains its title, shows both versions and disables saving until review. Keeping local edits retains the winner's independently changed property, makes no write until explicit save, and advances one further version. Adopting the latest version immediately replaces all displayed fields without another write. Reloading both clients confirms the same durable result.

The browser cases use two tabs of one synthetic account; the PostgreSQL contract separately exercises two authorized accounts. These results do not establish a cross-account browser workflow or realtime convergence.
