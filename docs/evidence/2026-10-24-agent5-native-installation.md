# Linux user installation and isolated native runtime

24 October 2026. Bounded #2/#79 qualification; F36 and M14 remain unfinished. The [installer](../../desktop/scripts/install-user-linux.py) now accepts an explicit absolute `--binary` path for builds outside the default Cargo target. Existing default selection and per-file atomic copying remain. Missing, relative, control-containing or symbolic-link selections fail before installation; an unreadable existing launcher fails without exposing its path or replacing files. The [desktop guide](../../desktop/README.md) documents the supported invocation and refusal boundaries.

## Executed checks

The [eleven installer subprocess tests](../../desktop/scripts/test-install-user-linux.py) passed without skips on Python 3.14.4, with private HOME/XDG fixtures and synthetic executable bytes. They cover explicit/default selection, exact copied bytes/modes, desktop-entry escaping, managed updates, preserved unrelated data, unmanaged or unreadable destinations, invalid or inaccessible sources, validator/cache failures and temporary-file cleanup. The unreadable-launcher regression first failed on the preceding proposal: it observed a traceback/path disclosure with no executable written. The narrow inspection guard corrected it; the intermediate ten-case suite passed. Review then identified that [Python 3.12 file predicates propagate permission errors](https://docs.python.org/3.12/library/pathlib.html#pathlib.Path.is_file), while [Python 3.14 suppresses them](https://docs.python.org/3.14/library/pathlib.html#querying-file-type-and-status). Source metadata inspection is now guarded too, with an inaccessible-parent case and recorded Python version. That case already refused privately on the local 3.14 runtime; older-Python execution remains for fresh Ubuntu CI. The CI scope job runs the suite before deciding which required checks execute. Synthetic bytes and substituted failure tools do not qualify native execution or real desktop tools.

The separate [allowlisted runtime receipt](2026-10-24-agent5-native-installation.json) records actual Linux amd64 execution. A locked release build from `590725e9` produced the 28,498,816-byte client with SHA-256 `6d66dcfad60410ae21abfe61210fe19af73c6a120a7e9fbe19279304076e6112`. Production desktop Rust and bundled frontend bytes are unchanged by this installer increment. A private installation copied that genuine executable and icon with the expected modes. Real desktop-file validation, cache update, private handler queries, the installed WebKit window, development-HTTP consent controls, desktop-ID launch and URI dispatch passed. The final installer revision also passed a managed-update recheck with identical file hashes/modes and replaced file inodes. No application rebuild or repeated GUI matrix was needed for that inspection-only correction.

The production SystemVault separately completed set/get/delete and absent-entry checks twice against an actual private Secret Service provider. A passwordless provider restart reloaded the empty persisted collection as locked; same-password bootstrap then allowed the second round trip. This does not prove a live credential survives restart. No credential references or values are included in public evidence.

## Failures and limits

Earlier fixture failures remain recorded: native text comparison required trimming; provider startup order and an overlong Unix socket path prevented initial vault readiness; owned orphan reaping was needed for strict provider shutdown. Isolating desktop search paths initially hid GTK settings schemas and image-codec configuration. Exposing the existing read-only resources corrected those setup failures. An initial compositor frame and a blank desktop-only capture are excluded from visual acceptance. Settled installed-window and URI images were reviewed privately for pixels and metadata; no screenshots, private paths, bearer values or raw provider output are published.

The qualified client and vault workers ran nonroot with no effective capabilities and no sandbox disabling; the namespace coordinator retained its local mount setup authority. Owned PID namespaces, mounts, sockets and private keyring data were checked and cleaned; host profiles and associations were not changed. This qualifies the recorded private Linux profile, installed first-connection UI and bounded URI dispatch. Authenticated native golden workflows, live-credential restart, hostile-page IPC, physical IME/assistive technology, other operating systems, reference performance, signing and invalid-update rejection remain unverified. Exact-head hosted checks, integration and an integrated installer recheck are still required for this code increment; no issue, milestone or full-product completion is claimed.
