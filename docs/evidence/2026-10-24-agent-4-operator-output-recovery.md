24 October 2026. Bounded #7/#46 qualification delegated by Agent 5, which retains recovery/M08 ownership. No production, Compose, schema, authorization or migration change is introduced.

The controller validates only its receipt; bearer bytes never leave the private volume/helpers/backup storage. The helper requires one nonempty regular artifact, directory ownership `10001:10001` with mode `0700`, and file ownership `10001:10001` with mode `0600`. Public checkpoint receipts contain no artifact name, code, raw CLI receipt, checksum or manifest.

All eight selected volumes are archived only after source services stop. Source mounts remain read-only. Checksums, traversal/type restrictions, empty-target refusal and exact inventory/bytes/ownership/mode comparisons remain. Optional-output archive permissions and inventory are checked before extraction. Restore verifies populated output before any initializer; the actual networkless output initializer runs without dependencies, followed by another exact comparison against the original private archive. No restored operator provisioning or grant step can mask missing database authority.

Source review identified that killing a timed-out Docker client does not guarantee its one-off container exits. Both new operations therefore have exact owned names and labels, preexisting-name refusal, bounded removal and confirmed absence in `finally`; interruption cleanup recognizes those same names. Handled SIGTERM/SIGINT unwinds these guards; SIGKILL or unavailable Docker requires the later workflow cleanup retry. Cleanup verifies project/service labels, network and exact volume mounts before removal. Private CLI failures are reported generically, and the dedicated actor cookie jar is always cleared.

The accepted [grant-removal](2026-10-22-agent-4-private-team-recovery.md), [private-move](2026-10-23-agent-4-private-move-recovery.md), event-admission and [cold-recovery](2026-10-22-agent5-offline-recovery.md) controls remain, including original reader sessions, destination/public controls, authority fingerprints, offline relay, blob fault repair, source restart and labelled cleanup.
