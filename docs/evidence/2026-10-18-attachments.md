# Files and interaction stability

Date: 18 October 2026. This increment implements the local F13/M04 upload lifecycle in the shared browser/desktop client, alongside repairs for the reported flicker and awkward editing transitions. It does not close the complete-product goal or the remaining M04, platform, scanner and recovery gates.

## Implemented behavior

Issue descriptions, new issues and comments accept files through the actual browser or native picker. Serial uploads show real transport progress, preserve the insertion position and surrounding typed text, and insert a reference only after the server reports ready. Interrupted responses reconcile the same reservation; scanner outages retain quarantine with an explicit retry. Pending uploads participate in draft guards. Cancellation shows progress, prevents duplicate confirmation, and keeps the draft with a visible retry when cleanup cannot be confirmed. Downloads are checked against their size and SHA-256 before saving. HTML is downloaded as inert bytes; there is no active preview.

The toolbar keeps its attachment-button slot while editing is temporarily disabled. Newly ready cards use a bounded, short-lived receipt seed scoped to the exact workspace and authentication/request revision, while their metadata is reauthorized. Scope changes replace card state synchronously. A previous download completion cannot clear a newer download's busy state. The account menu consumes Escape and returns focus to its summary; it no longer closes the issue behind it. Appearance buttons have explicit accessible labels. These extend the earlier [stylesheet, refresh and layout repair](2026-10-18-ui-refinement.md).

## Storage, privacy and migration

Migration 0017 adds workspace quota accounting, upload metadata, immutable document/revision references and private storage-operation receipts. Quota reservations serialize under a workspace lock. All ready transitions, linking, deletion and cleanup acknowledgments require the applicable current authority and generation/lease fence, with mandatory audit and event effects in the same database transaction. No database transaction spans filesystem or scanner I/O. Historical private references and comment audiences remain restricted after issue moves. Deleted references may remain visible as unavailable markers but cannot be reintroduced after removal.

Local storage is outside source/static directories, service-owned and 0700. It rejects unsafe roots, symlinks and hardlinks, verifies exact length and hash, and publishes read-only immutable files durably. Optional ClamAV uses its Unix-socket INSTREAM protocol; a configured scanner failure never downgrades to unscanned success. An unconfigured scanner is explicitly reported as Not scanned. Downloads reauthorize after disk verification and carry attachment disposition, octet-stream, no-store, nosniff and sandbox CSP. Eight admitted transfers and bounded channels constrain streaming. An independent 180-second producer deadline releases the file lock and transfer permit even if the response body is never polled. Cleanup has one retained blocking lane and a 30-second stage wait; quota is released only after durable removal/missing acknowledgment under a live lease.

API/worker refuse schema 16 before serving new behavior. Deployment and rollback must keep the database, immutable blobs and storage lock/tombstone files together. For a populated schema 17 instance, a database-only restore is incomplete; pause mutations and workers before taking a coordinated backup. The pre17 development backup has no attachment objects. There is no destructive down migration or automatic rollback over subsequent user work.

## Limits

The ClamAV fixture proves protocol and failure handling; no installed production antivirus service was exercised. A real file-write failure is covered with RLIMIT_FSIZE, not a full-disk mount. Native core and package checks do not prove rendered native dialogs or a native GUI workflow. Windows/macOS, signed distribution/updater, coordinated populated-blob disaster recovery, full IME/zoom/accessibility/performance qualification, mentions and templates remain open.
