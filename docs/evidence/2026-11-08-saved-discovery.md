# Saved views and search increment

This M06-T02 increment adds `/views` and `/saved-searches` under the ordinary workspace API. Both persist stable UUID definitions; only views may have team/workspace audiences. Personal saved searches and their favorites remain owner-scoped even when all matching issues are public. Sharing a view does not share its source data. Current workspace/team authority applies to every run, list and detail read.

Definitions store the existing versioned `IssueQuery` AST plus layout, grouping and visible-column settings. Query continuation cursors and evaluation clocks are ephemeral. Unsupported stored schema and inaccessible/deleted references return generic repair metadata with no executable AST; execution fails until an editor explicitly repairs it. Shared recipients do not receive inaccessible target identifiers. Full updates use `If-Match` and an idempotency key; audiences and owners cannot change in place. Favorites reference UUIDs, so rename does not replace a shortcut. Personal management is paginated and each owner may keep at most 100 searches per workspace.

`GET /search`, `POST /search/query` and `GET /search/suggestions` search authorized, live, nonarchived issues and projects. Exact current/historical issue keys rank first and return the current canonical key. Weighted title/body PostgreSQL full-text results use deterministic, authenticated keyset cursors bound to principal, workspace, query and authorization epoch. Issue filters reuse the Rust structured compiler. Search text is limited to 256 characters and 32 whitespace-separated words, results to 100 and suggestions to 20. Search statements have a 1,000 ms PostgreSQL deadline; failures remain recoverable errors. Project bodies use current documents, not retained legacy narrative snapshots. Snippets are plain text and React renders them as text.

The connected issue-screen panel supports explicit save/reopen/rename/delete, favorite controls, read-only shared definitions, conflict/retry states and full-text search-to-detail navigation. It loads definitions only when opened. Cached names/results and pending requests are scoped to principal, workspace and authorization epoch; denial clears saved names and snippets. Changing a reopened definition or search text marks unsaved overrides. Layout/filter state uses the existing URL fragment transport. Custom column/group rendering beyond the existing list/board presentation remains a later discovery UX gate; stored definitions preserve those typed settings.

Fuzzy title matching is explicitly unavailable in this first increment: responses set `fuzzy_degraded:true` with a notice while exact and FTS continue working. No pg_trgm extension, public database function or broader worker capability is installed. F24 fuzzy qualification and complete M06 remain open. Browser, load and executed validation receipts are recorded in the task handoff; builds and component tests alone are not browser or native-shell evidence.

Migration 0035 adds the saved-definition/favorite tables with scoped foreign keys and FORCE RLS, plus rebuildable generated FTS projections/indexes on issues, project titles and current project documents. It preserves earlier migration files. Source rows are retained. Roll back application code while retaining the additive schema, or restore the pre-upgrade backup for a schema rollback; dropping tables discards definitions/favorites and dropping indexes alone does not discard source text.


Personal definition/favorite mutations persist an owner-only `discovery_personal_events` row and advance `discovery_personal_heads`. The workspace stream event is `discovery.personal_changed`, with `entity_id` set to the affected principal UUID and `entity_version` to that user's monotonic discovery head. Neither private definition UUIDs nor names/AST appear in that stream event. Shared view mutations emit `view.created`, `view.updated` and `view.deleted`, with the shared view UUID, its definition version (deletion increments it once) and its team audience where applicable. `discovery_view_sources` retains only owner/audience/version/deletion facts after deletion. The realtime registry must call `store::discovery_event_visible` under current scoped authority for these four event types; personal checks match the current principal, shared checks use the retained audience and current team access. This worker does not edit realtime handlers. Browser delivery/registry integration remains a parent gate.

## Executed local load sample

The explicit `discovery_load` test seeded 100,000 real issue/document pairs in 500-row transactions: 70,000 in a second tenant, 27,000 in an inaccessible private team and 3,000 currently visible. PostgreSQL 18.6 ran on Linux x86_64 with 128 MiB shared buffers and JIT disabled; the local CPU was an Intel Core i7-11700F. This was a shared development host, not controlled reference hardware. The first single 70,000-row seed statement exceeded its explicit 120-second fixture deadline; bounded 500-row fixture transactions completed the real corpus without disabling source constraints/triggers.

Twenty-five full application requests per shape measured the normal guarded API use case, current permission joins and authenticated keyset result construction. No sampled request failed. Local p95 was 33.24 ms for selective `quasar`, 36.76 ms for common `nebula`, 29.45 ms for exact `GRA-100`, and 27.86 ms for an absent term. These samples do not qualify reference hardware, concurrent load, cold-cache behavior or full F24 relevance/fuzzy acceptance. [Raw summary](2026-11-08-discovery-load/summary.json) and the four adjacent `*-plan.json` files retain actual `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` from the same bound production query builder; measured plan execution ranged 13.23–19.18 ms. No unexecuted target is represented as a result.
