# Browser and desktop integration — 18 October 2026

The user requested both an application and a website. [ADR-017](../adr/017_DESKTOP_BROWSER.md) selects a Tauri 2 package with shared React assets and a chosen OpenTrack server. This increment brings F36 forward; it does not complete the remaining product or platform scope.

## Implemented boundaries

- A separate `desktop/` Rust workspace packages the interface without bundling a database or Node server. The Linux packager builds assets in a private temporary directory rather than replacing live web assets.
- A bounded native transport accepts only supported relative API routes, methods and headers. Server selection owns the origin. TLS verification and no-redirect requests prevent credentials from following a response to another server. HTTP requires explicit loopback development selection.
- Native sign-in uses the system browser, matching confirmation codes, random state, PKCE S256 and a one-use expiring exchange. Browser and desktop sessions have separate audiences. Cookie/bearer ambiguity is rejected; browser-only account entry points retain their browser/Origin requirements.
- Migration0013 upgrades existing sessions as browser sessions and adds native grant state and device metadata. Native issuance, consumption, audit and revocation use the existing account guard and transactional write checks. Revocation, recovery, account disablement and access elevation apply to both audiences.
- Native credentials live in the OS vault. Configuration contains an opaque reference only. Generation fencing isolates servers, while a separate scope generation preserves drafts during same-user reauthentication. Ambiguous writes retain their idempotency identity.
- Packaged pages have an explicit IPC capability list and CSP; remote navigation, frames and additional webviews are denied. Issue deep links are validated references and require review; they do not grant trust or authenticate.
- Browser **Account security** names desktop devices. Issue headers offer an **Open issue in desktop app** link. Native sign-out removes its credential; self-revocation is reported without sending browser cookie mutations.

## Credential queue repair and live saved-connection check

After approval in the real desktop workflow, the user reported “The system credential store is unavailable. Unlock it and try again.” Inspection showed a saved native credential reference; both debug and full-feature optimized real-vault probes passed. The failure was reproduced by a deterministic test on commit `d3eb8cd`: one vault read was held while a second authenticated request started, and the second immediately failed instead of waiting. The shared workspace intentionally loads bootstrap and access in parallel, exposing the native bridge's incorrect use of `try_acquire` on its single vault lane.

The bridge now serializes normal credential operations through a queue limited to 32 active/waiting calls, with a single ten-second deadline across waiting and execution. Overload reports a distinct retryable busy result. A blocking OS operation retains its lane after caller timeout; late credential cleanup and server/account fencing remain required. New regressions cover concurrent authenticated requests, a saturated queue followed by a server switch (with no stale dispatch), and a timed-out write that reports failure promptly while its late cleanup remains bounded. The original 26 native tests plus three regressions passed (29 total), and all-target Clippy passed. The root failure is application concurrency, not evidence that the user's keyring was locked. The corrected release package built successfully, was extracted and validated, and was installed atomically for the current user. Its executable matches the release output and the packaged executable differs only by Tauri's bundle marker. Only the owned failed native window was restarted; saved connection metadata and the credential were retained.
