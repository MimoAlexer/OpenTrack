# Identity and API contract evidence — 17 October 2026

This increment extends the foundation at `4d2dd84`. It is not a complete M02 or a release certification. The commit containing this record identifies the implementation under test; configuration work is a separate increment.

## Implemented scope

Migration 0004 adds versioned workspace/team/member lifecycle, organization membership, reserved team prefixes, invitation hashes and authorization epochs. The Rust application and HTTP API implement workspace creation/rename/archive/restore; public/private team creation and membership; workspace member roles/deactivation; invitation preview, issuance, revocation and one-time acceptance. Private-team administration still requires actual team access. A deferred database constraint and serialized authorization guard preserve an active workspace owner.

The React settings use these APIs with strong version preconditions, bounded directory pages, cancellation on scope changes and explicit password confirmation. A two-second visible-tab access poll clears scoped forms/data after an authorization epoch change. This is polling, not completed SSE delivery. Archived team issues retain their metadata, appear in the archive projection, remain readable and cannot be edited until the parent is restored.

Rust DTOs and route annotations produce `docs/api/openapi.json` and `web/src/generated/api.d.ts`. The check script regenerates and compares both. Responses use RFC 9457 problem bodies, local request IDs and consistent extraction/status errors; 201 Location URLs have readable canonical resources. Invitation tokens are accepted in request bodies rather than URLs. An issuance retry returns the original metadata with `token: null`: raw invitation secrets are never stored in idempotency responses.

## Browser observations and corrections

The built application was tested against the actual local API on port 18970. Incorrect password confirmation left the current session and workspace creation fields intact; correct confirmation allowed explicit retry and created a separate workspace with its initial team. Renaming preserved its UUID and URL. Switching returned to the original workspace's issues and cleared the other workspace's teams/forms. A private team was created, archived, shown read-only in archived teams and restored. Workspace archive disabled editing and its restore control returned the workspace to active use.

The browser exposed an intermittent database cancellation failure after team archive: a connection returned to the pool with an open server-side transaction, and later session reads encountered a lock timeout. The five-second idle-transaction timeout eventually recovered the connection. A real PostgreSQL regression then reproduced the leak deterministically by blocking BEGIN on a controlled advisory lock, confirming contention, canceling the future and reacquiring a one-connection pool. Before the fix, the previous transaction-local workspace UUID remained present. The store-owned transaction guard now closes unfinished connections and reuses only connections whose COMMIT/ROLLBACK completed. Every runtime transaction entry point uses this guard. The regression passes, checks replacement/reuse and verifies an abandoned insert is rolled back.

Review also found that generic mutation retries could reload a form and lose its draft, and archived workspaces still offered team/member/invitation mutation controls. Both were corrected with frontend regressions. Dirty team settings now block membership mutations until save/discard. Failed bootstrap refreshes withhold cached settings while permission polling continues. Reauthentication messages distinguish a rejected password from an expired session and prompt an explicit retry after successful confirmation; dialog cleanup restores focus even when the original trigger disappears.

At a 390-pixel emulated viewport, document width equaled viewport width. Team settings remained readable without horizontal page overflow. This is browser reflow evidence, not native mobile qualification.
