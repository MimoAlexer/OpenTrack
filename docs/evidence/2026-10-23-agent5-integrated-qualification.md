## Attachment failure invariant

The production storage adapter receives kernel ENOSPC on a private 4 MiB tmpfs. Failed publication leaves no staged or published object; removing the filler permits the same immutable key and exact bytes/hash. The real PostgreSQL/API case returns 503, preserves the same pending reservation with an updated validator, denies content, and later recovers that reservation to ready with one object.

The installed foreground ClamAV 1.5.4 fixture uses a private benign hash signature. Clean bytes become ready; a match is rejected. An actual daemon outage leaves bytes quarantined and unavailable, including another finalize while down. Restarting the same daemon/configuration allows the same reservation to recover; replay does not duplicate it. These are the fail-closed readiness paths required by F13-A3. The [detailed failure record](2026-10-22-agent5-attachment-failures.md) preserves namespace/version controls, corrected failures and process-session cleanup evidence.

F13-A3 is verified for this supported Linux server/API profile. This does not qualify physical-device/WAL exhaustion, every host filesystem, official CVD feeds or detection breadth. Native picker/window and broader failure UX remain separate #23/#25 acceptance obligations; those issues stay open.
