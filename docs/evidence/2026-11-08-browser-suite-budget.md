## Bounded correction

Before claiming or creating runtime resources, the parent runs credential-free Playwright JSON discovery with a 30-second watchdog. It validates all three complete serial projects, the unchanged 60-second case timeout, one worker, zero retries, no repeats, forbid-only, no skipped/expected-failure cases or collection errors, unique case identities and bounded output/traversal. Malformed, incomplete or excessive plans refuse startup.

The single absolute suite budget is `300 + 4 × discovered cases + 20` seconds: the existing full preparation allowance, a whole-second case throughput envelope rounded upward from measured aggregate timing, and a reserved diagnostic allowance. This gives 1,388 seconds for 267 cases, 1,520 for 300 and 1,796 for 369. Plans above the hard 1,800-second ceiling fail before runtime mutation and require explicit qualification partitioning; no test is silently omitted. This is an aggregate throughput gate, not a claim that every case simultaneously consuming its 60-second maximum fits the suite. The configured 45-minute CI job ceiling remains independent and unchanged.

Fixture preparation still consumes the same absolute deadline and cannot exceed 300 seconds. Node receives only the remaining shared time with 20 seconds reserved for diagnostics. The private admission state's finite lifetime ceiling is coherently 1,800 seconds; its unchanged 20-request/60-second accounting, phase limits, generation fencing, private-file locking and no-reset/no-retry behavior remain. Individual case/action/expectation/hook limits, retries zero, off-origin guards, credential filtering and exact owned cleanup are unchanged.
