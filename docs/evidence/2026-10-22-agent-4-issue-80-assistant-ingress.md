## Material protocol changes since the canonical baseline

The official latest-version URL now resolves to **2026-07-28**. A current specification is not evidence that a particular installed assistant supports it. [Published specification](https://modelcontextprotocol.io/specification/2026-07-28).

| Boundary | Current documented change | Consequence for later implementation |
| --- | --- | --- |
| Lifecycle/version | Modern requests carry `params._meta` fields `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities`; `initialize` is removed. Servers implement `server/discover`; unsupported versions produce error `-32022`. Earlier clients still use initialization. [Versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning). | Pin the selected client, server library and supported protocol revision together. A later ADR must choose a tested modern contract or explicitly tested legacy compatibility. Do not combine the two wire lifecycles. |
| HTTP transport | Single POST endpoint; no protocol session or GET stream. `MCP-Protocol-Version` must match body metadata; `Mcp-Method` is required, and `Mcp-Name` is required for `tools/call`, `resources/read`, `prompts/get`. Validate mirrored headers against the body; mismatch is HTTP 400 / `-32020`. Validate Origin; local binding should remain loopback. [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). | Do not use connection state, client headers or a session ID as authorization. Missing Origin on a non-browser client does not grant access. Preserve authentication and host/Origin policy independently. |
| Recovery/results | SSE event-ID resumability/redelivery is removed; a broken stream requires a new request ID. Results carry `resultType`; change notifications move to `subscriptions/listen`, and tasks move to an extension. [Changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog). | New JSON-RPC IDs are not business idempotency keys. Preserve reviewed write receipts across ambiguous retries. Do not adopt optional tasks, sampling or subscriptions merely to expose basic read tools. |
| Catalog/schema | Tool lists can vary with the request's authorization, not connection history. Cacheable lists carry `ttlMs` and `cacheScope`; schemas use JSON Schema 2020-12. Tool annotations are hints, not authority. [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools). | Authorized tool catalogs/results must not leak through shared caches. Keep schemas bounded and validate inputs server-side; metadata cannot override OpenTrack policy. |
| Registration/auth | CIMD is preferred when no registration already exists; DCR is now deprecated compatibility. Persisted pre-registered/DCR credentials are issuer-bound; an issuer change cannot reuse another server's client credentials. DCR must specify an appropriate `application_type`. [Registration](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration). | Test registration and issuer migration explicitly. Do not solve interoperability by accepting arbitrary redirect URIs, clients or resource values. |

## Required resource and authorization contract

| Requirement | Verified source requirement and OpenTrack boundary |
| --- | --- |
| Discovery | Protected Resource Metadata must identify the canonical MCP `resource` and authorized issuer(s). Clients discover it through a `WWW-Authenticate: Bearer resource_metadata="..."` challenge or path-aware/root well-known metadata. OAuth/OIDC metadata issuer must exactly match the issuer used for discovery. [Discovery](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/authorization-server-discovery). Publish only the selected deployment's configured URLs; do not derive authority from an untrusted Host header. |
| Resource/audience | Send the canonical MCP URI as `resource` in authorization and token requests. Accept only access tokens issued for this resource; use the Bearer header on every HTTP request, never query-string tokens. Reject unrelated tokens and token passthrough. [Baseline authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization). OpenTrack web sessions, desktop sessions, internal runner credentials, AI-provider tokens and MCP access tokens remain separate audiences/principals. |
| Code/PKCE | Require authorization-code PKCE S256 and advertised `code_challenge_methods_supported`; absence must not fall back to an unprotected flow. Use HTTPS authorization-server endpoints and exact registered redirects, with the documented native loopback exception. Protect each pending flow against CSRF and replay. [Security requirements](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations). |
| Issuer validation | Record the validated metadata issuer with the pending flow. Before code redemption, reject a mismatched returned `iss`; reject missing `iss` when issuer identification is advertised. Compare decoded issuer values without URI normalization. [Current authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization#authorization-response-validation). |
| Consent/scopes | Consent must bind the authenticated user, client, requested scopes and redirect. A trusted connection does not approve each consequential effect. The canonical initial scopes are `issues:read`, `projects:read`, `issues:write`, `comments:write`, `agents:request`, `agents:read`; grant only requested/approved scopes intersected with live membership and normal team ACL. Proxy consent must be per client, with CSRF/clickjacking protection; discovery/CIMD fetches need SSRF controls. [MCP security guidance](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices), [OpenTrack tools](../ai/EXTERNAL_ASSISTANTS.md). |
| Challenges/refresh | Missing/invalid/expired authorization is HTTP 401; insufficient scope is HTTP 403 with an appropriate challenge. Challenge scopes describe the current operation. Do not advertise `offline_access` as an MCP resource requirement; refresh tokens are discretionary and stay confidential. [Current authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization). Public-client refresh replay needs rotation; record single-owner replacement and restart/race behavior. [Refresh protection](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations#token-theft). |
| Revocation | Implement and verify grant/token revocation and local authorization fencing. RFC 7009's HTTP 200 covers successful revocation or an already-invalid token; a 503 leaves revocation unconfirmed. It does not establish how quickly every separately issued token is rejected. [Revocation](https://www.rfc-editor.org/rfc/rfc7009.html). F31-A2 requires actual membership loss to stop subsequent access even while a cryptographic token remains unexpired; JWT expiry alone cannot meet it. |

Current-tree source observation: [credential parsing](../../crates/opentrack-api/src/credentials.rs) maps Authorization Bearer to the Desktop credential path and rejects ambiguous credentials. [Application authentication](../../crates/opentrack-app/src/lib.rs) authenticates that path with the Desktop audience and rechecks session activity for workspace access. This is a native-session boundary, not an MCP OAuth resource-server validator. The later implementation must consume the #54/M10 public-principal/scope contract rather than reinterpret a Desktop bearer or bypass normal authorization. Existing native PKCE is not evidence of an OAuth authorization server.

## Minimum later qualification

- **Identity and authorization:** exact selected real client; successful permitted read/search; denied consent; expired/replayed code; wrong issuer/resource/audience; invalid/missing PKCE; wrong callback; insufficient scopes; cross-workspace/private-team denial; membership/grant revocation during a live connection and refresh. No cached catalog may preserve revoked data access.
- **Write safety:** version-bound reviewed proposals, current ACL recheck at Apply, idempotency key/body mismatch rejection, duplicate/ambiguous retry creates one effect, stale version cannot overwrite, and `request_agent_run` cannot skip the normal grant/review gate. Client approval UI is supporting evidence, not server authority.
- **Transport/version:** record actual negotiated legacy or declared modern revision; fragmented JSON/SSE, bounded schemas/results, unknown events, header/body mismatch, dropped stream, new request ID with preserved business idempotency, and authorization-server/metadata outages. A synthetic host cannot replace the selected-client journey.
- **Reachability and operation:** qualify local-only operation separately from any chosen remote path; test OAuth endpoints from every participant, callback routing, restart/refresh custody, disconnect/revocation, redaction and recovery. Component installation, network exposure and client registration require their own later authorized implementation step.
