## Status rules

- **Unverified**: no adequate implementation/runtime evidence recorded here. This is the initial status, not a claim about files another worker may currently be editing.
- **In progress**: work is underway; record owner/current source and unresolved behavior.
- **Implemented / unverified**: source exists but acceptance evidence is incomplete.
- **Verified**: exact source/revision, environment, executed check and observed outcome are linked; required negative/failure tests pass.
- **Blocked**: name the unavailable external dependency or user decision, work already completed and remaining verification. Continue independent work. A blocked row is not complete.

Record evidence under docs/evidence/ or an existing exact source/test path. Preserve command output summaries, browser/native screenshots where useful, failure/fix/recheck references and limitations. Do not mark live-provider, native OS, concurrency or restore checks from mocks or build results. Scope changes require the user's explicit direction and a recorded rationale; never delete a requirement to manufacture completion.
