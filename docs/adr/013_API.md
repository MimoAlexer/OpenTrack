# ADR-013 REST contracts, versions and explicit idempotency

Date:2026-10-17. Status: Selected Phase 0 baseline; not implemented.

## Problem

UI, integrations and future desktop clients need predictable durable writes and conflict recovery.

## Options and tradeoffs

GraphQL offers flexible reads but adds query complexity/security budgets and generation choices. Ad-hoc RPC is easy initially but obscures compatibility. REST plus typed actions and OpenAPI meets current needs; SSE handles invalidation.

## Decision

Use /api/v1 with problem+json, ETags/If-Match, scoped Idempotency-Key, keyset cursors, validated filter AST and generated TS types. Internal runner audience remains separate.

## Consequences and risks

Endpoint count is substantial but domain service reuse prevents divergence. Whole-entity versioning creates some avoidable conflicts; correctness and explicit merge take priority. Public API does not mean anonymous data.

## Reconsideration and validation

Revisit GraphQL only for demonstrated client query needs, not fashion. M03 contract/race tests; M10 developer-token scopes. [Problem details](https://www.rfc-editor.org/rfc/rfc9457.html).
